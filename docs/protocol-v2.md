# Prospective collection protocol v2 — proposed next collection

Prepared October 29, 2026. Not applied retrospectively to v1. Freeze a dated version before recollection; document deviations and amendments.

## Objective and units

Describe concrete sleep-related disclosures in a bounded set of official hotel pages. The primary unit remains property × domain, with individual claims nested within each unit. This is not a guest findability, comprehension, room-performance or sleep-outcome study.

## Eligibility and sampling

Verify current operation and municipal boundary before collection. Establish the source and construction of the eligible frame. Retain the original pilot for method comparison; do not replace inaccessible properties opportunistically. Justify any larger sample against the intended inference. Use varied website structures for instrument testing; do not call a purposive panel representative.

## Collection and completion rule

Use the same sequence for every property: official overview, accommodations, room details, amenities/FAQ. Record canonical/final URL and duplicate redirects. A failed guessed URL is an attempt, not a successfully reviewed page. Record any targeted query verbatim and the route to a discovered page. Up to four relevant distinct pages, excluding duplicate redirects; document excluded relevant pages and why the limit was reached. Record room types inspected and whether availability or selected dates restrict visible content. Do not make a booking.

First inspect rendered public content with relevant panels expanded. Retain a permitted research capture of the relevant text/context or screenshot, access method, precise UTC time, language/device context and section locator. Use extracted text as an aid and document disagreements with rendering. No security bypass, paywall bypass or account login is required. If a relevant panel remains unavailable, mark coverage partial and explain domain relevance. Retry once using an ordinary alternative route and record the result. A negative classification requires completed scope and retained supporting review material; otherwise use undetermined. Preserve captures for review with appropriate access and rights handling; public excerpts need not reproduce full pages.

## Separate coding dimensions

Disclosure: specific, vague, not found in completed scope, undetermined. Coverage: completed scope, partial, unavailable. Claim type: policy, physical feature, material/specification, control, request mechanism, explicit limitation, promotional wording. Record room scope, conditions, contradictions and actionability separately. Do not resolve conflicting claims by retaining only the most specific. Specific does not mean useful, true or fulfilled.

Noise: distinguish policy, acoustic feature, placement and advisory. Light: distinguish daylight exclusion from artificial-light control. Temperature: distinguish system presence from individual control. Bedding: distinguish material/type from brand name and quality adjectives. Choice: require an explicit sleep-related option or request mechanism; record conditions and avoid inferring fulfillment. Equal display does not imply equal effects on sleep.

## Reliability and analysis

Train reviewers on separate examples, freeze the codebook, then independently code the same evidence packets while blinded to prior labels. Independently repeat discovery for a subset to detect omissions. Retain all pre-adjudication labels, a disagreement table and category-specific agreement. Any chance-adjusted statistic must acknowledge small sample size, class imbalance and clustering within properties; do not treat 25 cells as 25 independent hotels. Preserve access failures in denominators; no imputation, ranking or citywide inference from a purposive pilot.

Prioritize sensitivity to retrieval route, page scope, room-specific exceptions and partial coverage. Do not redefine vague adjectives as specific merely to generate another headline.

## AI and human contributions

Record model identifier when available, prompt version, tools, collection date and actual human review contribution. Never invent missing historical metadata. AI review is not independent human verification. Suggested coding instruction: “Classify only retained official-source evidence. Quote and locate support for each positive claim. Do not infer a missing amenity. Treat incomplete relevant coverage as undetermined. Separate source access, claim type, room scope and actionable control. Preserve contradictions and competing interpretations. Return evidence gaps for review rather than completing them from general knowledge.”

## Later validation

Assess guest interpretation with a separately specified task and recruitment/consent plan. Assess room conditions with a separate measurement protocol. Any health or commercial outcomes need their own design, confounder strategy and appropriate participant protections. None begins under this website audit.
